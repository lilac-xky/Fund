## 1. 结论（先给判断，再给依据）

**结论：部分可用，不是一刀切的"达标"或"不达标"。必须按类型分档，且原始方案（重仓股 + 指数残差）在指数基金上是错的。**

| 类型 | 能否达到 0.3 个百分点 | 应采用方案 | 实测 MAE |
|------|---------------------|-----------|---------|
| **股票型／场内 ETF（被动）** | ✅ 能，且余量很大 | **直接用对标指数**，不用重仓股 | 0.031 |
| **红利** | ✅ 能 | 全量持仓加权，残差按 0 计 | 0.072 |
| **债券型** | ✅ 能 | 债券 ETF 代理或纯指数 | 0.009 |
| **黄金** | ⚠️ 临界 | 黄金 ETF 代理 | 0.155（P90 0.320 略超阈值） |
| **混合型** | ❌ 不能 | 全量持仓加权（残差按 0）为最优，仍 0.29~0.36 | 0.293 |

**三条对后续 issue 有直接影响的结论：**

1. **"残差按指数补齐"这个原始口径是错的，应改为"残差按 0 计"。** 中报／年报披露的是**全部**股票持仓，`1 − 重仓股占比合计` 那部分不是"没披露的股票"，而是**债券与现金**。按指数补这部分会给所有基金引入系统性偏差。实测 510300 用指数补残差时 MAE 0.307，改为按 0 计降到 0.218；161725 从 0.054 降到 0.047；005827 从 0.335 降到 0.242。这条直接决定 ISSUE-007 的算法实现。

2. **被动指数基金不该走"重仓股 + 指数"这条路，直接用指数更准。** 510300 用指数 MAE 0.015，用重仓股 0.206，差一个数量级。原因是季报只披露前十大（覆盖 51%~71%），剩下的部分靠推算必然失真。ISSUE-007 应为指数型基金单独开一条"指数直取"分支。

3. **混合型达不到 0.3，这是硬约束，不是实现问题。** 最优方案 MAE 0.293、P90 0.563、命中率 57.5%。混合型主动调仓频繁，季度持仓与当日实际持仓的偏离无法用任何加权方式弥补。意味着 PRD 第 7 节"混合型误差 ≤ 0.3"这条验收标准**按现状无法满足**，需要产品侧决策（见第 6 节）。

## 3. 债券型建议阈值（验收标准第 3 条）

**建议阈值：0.10 个百分点（绝对误差），而非放宽到 0.3。**

依据：

- 债券基金日波动极小。实测 180 个交易日，|当日涨跌| 中位数 **0.015**、P90 **0.061** 个百分点。
- 预估误差：MAE 0.006~0.043、P90 0.014~0.097（3 个月窗口，40~60 个交易日）。**误差与信号本身同量级**。
- 若阈值设 0.3，等于「误差比日波动大 20 倍也算合格」，阈值失去意义——这正是访谈记录第 4 轮指出的矛盾：*"如果债券基金的日波动小于预估误差，那么预估涨跌对债券基金没有使用价值"*。

**更重要的建议：债券型不该做当日预估。** 这与访谈记录第 5 轮的结论一致（债券基金改做"该不该持有 + 横盘转弱提醒"）。本次实测支持这个决定：预估误差与信号同量级，预估值提供的信息量接近于零。

若产品上仍要显示，建议：**阈值 0.10，且只在误差 ≤0.05 时标注"可信"，其余一律只显示"已更新"不给数字。**

## 4. 披露期与误差的关系（验收标准第 4 条）

**结论：未观察到"披露后第 N 日起误差明显放大"。误差随披露后天数的秩相关系数全部在 ±0.21 内，无一致方向。**

秩相关（|误差| vs 披露后交易日数，每只基金 60 个交易日）：

| 基金 | 类型 | Spearman ρ |
|------|------|-----------|
| 100032 富国红利增强 | 红利 | +0.201 |
| 003095 中欧医疗健康 | 混合型 | +0.068 |
| 510300 沪深300ETF | 股票型 | +0.041 |
| 163402 兴全趋势 | 混合型 | +0.029 |
| 090010 大成中证红利 | 红利 | −0.207 |
| 320007 诺安成长 | 混合型 | −0.170 |
| 005827 易方达蓝筹精选 | 混合型 | −0.073 |

按披露后天数分桶的 MAE（百分点）：

| 类型 | 0-5 日 | 5-10 日 | 10-20 日 | 20-40 日 | 40+ 日 |
|------|--------|---------|----------|----------|--------|
| 股票型 | 0.161 | 0.262 | 0.129 | 0.099 | 0.125 |
| 红利 | 0.213 | 0.210 | 0.189 | 0.171 | 0.180 |
| 混合型 | 0.543 | 0.859 | 0.370 | 0.392 | 0.420 |

**解读：**

- 若持仓滞后是主要误差源，误差应单调上升。实际**没有一致单调性**：股票型在 20-40 日处最低（0.099）、5-10 日处最高（0.262）；红利全区间基本平坦（0.171~0.213）。
- 混合型 5-10 日档 MAE 0.859 异常高，但该档只有 20 个样本、且落在 2026Q2 披露后的一段高波动期，不能归因于持仓滞后本身；40+ 日档 0.420 与 0-5 日档 0.543 相比并未上升。
- **对 ISSUE-007 的影响**：不必按"披露后第 N 日"做可信度衰减，可信度标注应改用**覆盖率（Σw）与误差历史**两个因子。这修正了原计划"依据披露距今月数"的假设。

## 5. 探针过程中发现的、文档未记录的数据源事实

这些事实直接影响 ISSUE-005 / ISSUE-006 / ISSUE-007 的实现，须回写 TECH-PRD：

### 5.1 `Data_fundSharesPositions` 不是重仓股权重，是股票仓位时序

TECH-PRD §11.1 与 ISSUE-001 原文均称从 `pingzhongdata` 解析 `Data_fundSharesPositions` 得到"重仓股及占比"。**实测该字段是「股票仓位随时间变化」的两列数组**，例如 005827 的最后一项是 `[1792598400000, 95.00]`，即"某种仓位 95%"，不含任何个股。

真实的重仓股权重必须走另一个接口：

```
https://fundf10.eastmoney.com/FundArchivesDatas.aspx?type=jjcc&code={code}&topline=100&year={year}&month={month}
```

该接口返回 HTML 片段，需解析 `<table>`。`topline` 取值 10 或 100 决定返回前十大还是全量。

`pingzhongdata` 中与持仓真正相关的字段是 `Data_assetAllocation`（季末股票/债券/现金占净比），这才是"仓位"的权威来源。

### 5.2 季报只披露前十大，中报与年报才披露全量

| 报告 | 披露内容 | 实测例子（090010） |
|------|---------|-------------------|
| 一季报 / 三季报 | **仅前十大重仓股** | 2026Q1：15 行，合计 16.9% |
| 中报 / 年报 | 全量持仓 | 2026Q2：100 行，合计 94.3% |

**这意味着一年里有半年只能拿到"前十大 + 低覆盖"的数据**，这是生产环境的常态，不是异常。探针的滚动前瞻回测正是为此设计：每份快照只在「披露日 ≤ 日期 < 下一份披露日」区间内使用。

### 5.3 覆盖度 ≈ 股票仓位，证明"残差是现金不是股票"

| 基金 | 覆盖度 Σw | 季末股票仓位 | 差 |
|------|----------|-------------|-----|
| 003095 | 92.89 | 92.91 | −0.02 |
| 005827 | 76.43 | 76.43 | 0.00 |
| 090010 | 94.27 | 94.33 | −0.06 |
| 163402 | 91.01 | 90.99 | +0.02 |
| 320007 | 90.66 | 90.73 | −0.07 |
| 510300 | 71.08 | 95.92 | −24.84 |
| 510500 | 47.87 | 95.12 | −47.25 |

前 5 只（中报/年报口径）覆盖度与股票仓位**吻合到小数点后一位**——说明全量持仓已披露完毕，`1 − Σw` 就是债券与现金。**因此按指数补残差必然引入误差**，这是第 1 节结论 1 的直接证据。

后 2 只 ETF 是季报口径，只有前十大（覆盖 47%/71%），缺口是"未披露的股票"而非现金——但即便如此，直接取指数仍显著优于用重仓股拼。

### 5.4 东方财富 `push2his` 无法支撑批量取数，必须多源回退

实测连续请求约 20 次后开始返回 `RemoteDisconnected`，冷却数分钟仍拒绝；腾讯 `fqkline` 高频访问会返回 HTML 验证页（501）。最终采用三级回退：

- A 股/指数：腾讯前复权 → 新浪日线
- 港股：腾讯 `hkfqkline` 专用接口（通用接口对 hk 前缀会 501）
- 汇率（港币兑人民币）：新浪外汇日线（东财 `133.HKDCNH` 被限流，腾讯无历史）

**对 ISSUE-006 的影响**：原计划"东财 `push2` 一次请求取 10 只重仓股"不可行，需改为「腾讯/新浪多源 + 缓存」；且必须把"单源失效自动切换"作为验收项，不能只做接口封装。

### 5.5 港股重仓股必须计入汇率

005827 的 100 只重仓股中有 17 只港股。港币计价涨跌直接加权会漏掉汇率变动。已在 `probe/lib/estimate.py` 中实现 `(1+r_hk)(1+r_fx) − 1` 的复利折算。

### 5.6 基金代码 920xxx（北交所）在新浪与腾讯均无数据

090010、005827 的重仓股中出现 `920599`、`920136` 等北交所代码，两个行情源都取不到。这类标的应从加权中剔除（已实现：取不到当日行情则整只按缺数据处理），并在页面标注覆盖率下降。

## 6. 对后续 issue 的具体影响

### 必须修改的实现方式

| Issue | 原计划 | 应改为 | 依据 |
|-------|--------|--------|------|
| **ISSUE-005** | 从 `pingzhongdata` 的 `Data_fundSharesPositions` 取重仓股权重 | 改从 `fundf10/FundArchivesDatas.aspx?type=jjcc` 解析；`Data_assetAllocation` 取仓位 | §5.1 |
| **ISSUE-006** | 东财 `push2` 批量取重仓股行情 | 腾讯/新浪多源 + 本地缓存；东财仅作备用 | §5.4 |
| **ISSUE-007** | 重仓股加权 + `(1−Σw)` 按指数补残差 | ① 指数型走"指数直取"分支；② 其余按 `(1−Σw)×0` 计；③ 港股乘汇率 | §1 结论 1/2、§5.3/5.5 |
| **ISSUE-007 可信度** | 依据"披露距今月数 + 覆盖率 + 误差历史" | 去掉"披露距今月数"，改用"覆盖率 + 误差历史" | §4 |
| **ISSUE-008 债券阈值** | 使用者设定，可放宽 | 建议默认 0.10；且产品上重新考虑债券是否做当日预估 | §3 |

### 需要产品侧决策的三件事

1. **PRD 第 7 节的"混合型 ≤ 0.3"无法满足。** 最优方案 MAE 0.293 / P90 0.563 / 命中率 58%。三条路：
   - (a) 混合型降级为"只显示、不承诺精度"，明确标注"混合型主动调仓频繁，预估值仅供参考"；
   - (b) 放宽混合型阈值到 0.6（对应 P90）；
   - (c) 混合型改用"近 5 日净值外推"或其他方案（本次未验证，需追加探针）。
   **建议 (a)**：与 PRD 第 9 节"宁可不显示，不显示错数"的精神一致——混合型显示但不能当作 0.3 精度使用。

2. **黄金 P90 0.320 略超阈值。** 中位数 0.155 达标，但尾部超标。建议阈值维持 0.3，同时标注"黄金类预估值波动较大"。黄金联接基金与 ETF 之间有跟踪误差与现金拖累，这是误差来源，不是数据问题。

3. **债券型是否继续做当日预估。** 见第 3 节，建议不做。

### 探针本身的有效性说明

- **滚动前瞻，无前视偏差**：每份持仓快照只在披露日之后才用于预测。如果偷看未来（用当日已知的季度持仓回测披露前的日子），误差会显著偏低，结论不可信。
- **净值口径**：使用东财 `equityReturn`，已与官方 `JZJJL`（净值增长率）逐日比对，20 个交易日零差异。
- **复权口径**：K 线用前复权。实测不复权在除权日会产生假跳空（如 300308 在 2026-07-28 有 −15.7% 的非市场波动），会污染误差统计。
- **样本量**：每只基金 60 个交易日（3 个月，符合 ISSUE-001 要求），另做 261 个交易日（1 年）窗口复核，两大类的定性结论一致（指数型达标、混合型不达标）；具体数值以 3 个月窗口为准，因为那是验收口径。

## 7. 复现方式

```bash
# 全量跑一遍（读磁盘缓存，约 2 分钟）
python probe/run_probe.py

# 忽略缓存重新取数
python probe/run_probe.py --refresh

# 自定义回看窗口（自然日）
python probe/run_probe.py --days 400

# 生成汇总分析表
python probe/analyze.py
```

输出文件：

| 文件 | 内容 |
|------|------|
| `probe/out/detail_all.csv` | 逐基金逐日明细（预估、实际、误差、方案） |
| `probe/out/fund_summary.csv` | 基金 × 方案 的误差分布 |
| `probe/out/by_type.csv` | 类型 × 方案（对基金取中位数） |
| `probe/out/by_type_pooled.csv` | 类型 × 方案（交易日合并） |
| `probe/out/table_best_scheme.csv` | 报告第 2 节主表 |
| `probe/out/table_threshold.csv` | 阈值判定表 |
| `probe/out/table_coverage_vs_position.csv` | 覆盖度 vs 股票仓位 |
| `probe/out/decay_buckets.csv` / `decay_spearman.csv` | 披露期与误差关系 |
| `probe/out/bond_threshold.json` | 债券阈值依据 |

依赖：`Python 3.12`、`requests`。**不引入 akshare、pandas、numpy**——纯标准库 + requests，避免绑定 Python 运行时（符合 ISSUE-001 的约束）。
